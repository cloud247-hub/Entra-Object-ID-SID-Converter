SLIK FUNGERER DET

Samme byte-rekkefølge som .NET

Verktøyet følger samme prinsipp som Microsofts PowerShell-eksempel: GUID-en leses som 16 byte, deles i fire usignerte 32-bits heltall og får SID-prefikset S-1-12-1.

01

Les GUID

Object ID valideres og normaliseres til standard GUID-format.

02

Del i fire tall

De 16 bytene tolkes som fire little-endian UInt32-verdier.

03

Bygg SID

Delverdiene settes etter prefikset S-1-12-1.

73d664e4-0886-4a73-9731-8146e010541d → S-1-12-1-1943430372-1249052806-1182871959-492048608

Viktig avgrensning

Dette er en deterministisk formatkonvertering. Verktøyet kobler ikke til Microsoft Graph og bekrefter derfor ikke om objektet eksisterer, hvilken type objekt det er eller om det fortsatt er aktivt.

Ikke et on-premises objectSid

En S-1-12-1-SID er ikke det samme som en tradisjonell Active Directory-SID eller verdien i onPremisesSecurityIdentifier. Andre SID-formater kan ikke konverteres med denne metoden.

Bruk samme konvertering i terminalen

Last ned et PowerShell-script med funksjoner for begge retninger. Scriptet krever ingen Microsoft Graph-modul og gjør kun lokal konvertering.

function Convert-EntraObjectIdToSid {
    param([Parameter(Mandatory)][string]$ObjectId)

    $values = [UInt32[]]::new(4)
    $bytes  = [Guid]::Parse($ObjectId).ToByteArray()
    [Buffer]::BlockCopy($bytes, 0, $values, 0, 16)

    "S-1-12-1-{0}-{1}-{2}-{3}" -f $values
}
